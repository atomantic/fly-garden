# Local recording storage contract (version 1)

Recordings are observations, never checkpoints. Version 1 uses an app-owned SQLite index and one bounded JSON chunk per sampled observation. Unknown index or export versions are rejected; there is no implicit migration. Future migrations must back up the store and validate before switching versions. Only this store's files may be deleted. Checkpoint files and identity state are never touched.

Recording starts only on an explicit request. Restart marks interrupted recordings partial; it never resumes recording or simulation. Stop is complete only if no samples failed. A global chunk byte quota, record count (10,000 by default), and session count bound retention: when full, recording stops partial until the operator explicitly deletes a recording. No automatic eviction hides evidence. The index contains bounded metadata; chunk writes are asynchronous and single-flight. A busy writer drops a sample explicitly instead of queuing neural observations indefinitely. Source windows, skipped sample counts, individual/world/wall times, model version, seed and checkpoint reference are preserved. Seed may be null when the fixture has no RNG.

Read/export/replay validates each indexed chunk's byte length and SHA-256 hash. Missing/corrupt chunks become explicit gaps and intact chunks remain readable. Replay returns inert data only and accepts no runtime, action, provider or credential capability. Shared recordings declare participating IDs; absent participants make an export partial. These are sampled observations, not a complete spike history or evidence of retained learning.

Exports are built from a strict allowlist of numeric telemetry and provenance fields. Arbitrary event prose, provider configuration and credentials are not recorded. The storage API is `createRecordingStore({ directory, maxBytes, maxSessions, maxRecords, maxChunkBytes })`; `start(provenance)`, asynchronous `append(id, observation)`, `stop(id)`, `list()`, `read(id)`, `export(id)`, `replay(id)`, `delete(id)` and `close()` operate on that store. Callers must await outstanding appends before closing. A service recording hook should sample snapshots without awaiting writes in the neural step path, and surface returned status/drop counts. Session IDs are generated internally and never treated as caller-provided paths.

The byte quota covers chunk payloads; SQLite has additional bounded per-record/index overhead. A source command-session ID is required on provenance and observations; a restore/new source session stops the recording partial. Crash recovery removes only unindexed files matching this store’s generated UUID chunk naming convention; unrelated checkpoint files remain untouched.
