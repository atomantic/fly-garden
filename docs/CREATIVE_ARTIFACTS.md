# Movement-derived music and pollen artwork

Version 1 is an original deterministic mapping from declared movement actions to notes and marks. It makes no learned-choice, preference, biological creativity or welfare claim. It cannot send neural input, move an individual, start simulation or invoke a provider. Decorative animation is not an eligible source unless explicitly supplied and labeled as an engineered controller by the caller. The module does not establish that the live fixture has an embodied movement loop.

`server/creative-artifacts.js` exports `validateCreativeSource`, `deriveCreativeEvents`, `exportCreativeJSON`, `exportCreativeMIDI`, `exportCreativeSVG` and `exportCreativePNG`. Export functions return bounded Buffers. JSON embeds the validated source and derived events; passing its `source` back to any exporter deterministically reproduces that format. Unknown versions, unknown fields and invalid numbers are rejected before deriving events. There is no restoration into a live runtime.

## Source contract

The source has schemaVersion 1, kind `movement-derived-source`, recording `sessionId`, `worldId`, `modelVersion`, nullable `checkpointId`, declared `participantIds`, a human `arrangement`, and ordered `actions`. Individual action session IDs may differ from the recording session and each other; they remain fixed per individual within one artifact. Each action supplies unique `id`, `individualId`, `sessionId`, `worldId`, `simulationTimeMs`, `worldTimeMs`, `wallTimeMs`, `kind` (`move` or `rest`), normalized `from` and `to` points `{x,y}`, and a disclosed `controllerVersion`. Global world times are nondecreasing; per-individual simulation times strictly increase and positions must be continuous. After a restore, use a new source artifact rather than joining incompatible trajectories.

The arrangement has stable `id`, `humanContributionId`, mappingVersion `flower-pollen-v1`, `flowers` and `pollen`. Each flower defines `id`, normalized `x,y`, `radius` (0.01–0.25), `midiNote` (0–127), velocity (1–100), durationMs (20–2000). Pollen defines `enabled`, a six-digit hex `color`, and pixel `radius` (1–8). These choices are attributed to the human arrangement, not inferred choices by the fly.

A note occurs only when an action's previous endpoint is outside a configured flower and its new endpoint is inside. Remaining within a flower, rest and zero movement produce no note. Pollen produces one line segment per nonzero movement when enabled. Crossings whose endpoints both lie outside produce no note: this is a disclosed endpoint mapping, not continuous collision detection. Overlapping flowers can emit separate notes. No minimum output, automatic reward, imitation requirement or escalating stimulation exists; any declared participant may contribute nothing.

Every event retains its source action ID, individual/session/world IDs, the three clocks, controller and mapping version, arrangement ID and human contribution ID. JSON carries the entire replay source. SVG embeds summary provenance and per-mark action/individual attributes; PNG embeds the JSON source/events in a metadata chunk. MIDI embeds summary and per-note provenance as text events, with fixed 500 ticks per quarter and 500,000 microseconds per quarter (one tick per millisecond). MIDI playback uses standard note-on/off events; overlapping identical pitches share the standard MIDI channel and may be interpreted differently by players. Artwork is original procedural geometry with no third-party assets.

## Bounds and integration

The module accepts at most 1,024 actions, 32 flowers, 16 participants, simulation/world timestamps through 3,600,000 ms, 8,192 derived events, a 256×256 canvas and 2 MiB per exported artifact. Rejecting an oversized result is explicit; callers must show the error and must not silently truncate or label it complete. PNG uses built-in zlib and a bounded RGB raster. These are artifact limits, not limits or obligations imposed on the neural worker.

The integration seam is a separate, explicitly requested export operation over retained accepted movement actions. Preserve source action IDs and source gaps from the session recorder; do not manufacture missing trajectory positions or treat a partial recording as complete. The caller chooses the versioned human arrangement and passes only the allowed fields. Keep export/replay entirely separate from the live command and provider APIs. HTTP/UI wiring and live action capture belong to the caller; this module alone does not activate live musical flowers.

Tests verify source attribution, silent rest, independent participants with separate source sessions, deterministic replay across all four formats, PNG raster decoding, and rejection of malformed/incompatible/discontinuous input. These are engineering tests; they provide no controlled evidence for learned creativity.

## Live fixture capture

The UI explicitly starts capture only after attaching and running the engineered visual fixture. `creative-session.js` retains accepted motor actions per individual, normalizing original garden coordinates from [-4,4] to [0,1]. Its preset matches the original garden's authored flower positions and attributes the five-note mapping to `project-garden-arrangement-v1`. No reward is attached to notes or marks. The capture ends with an explicit gap on session/epoch discontinuity or when its bound is reached; neural advancement is unaffected. Invalid candidate actions preserve the last valid trajectory.

Capture is session-local until exported. JSON, MIDI, SVG and PNG include optional source `capture` metadata (`complete`, `reason`); exports taken while capture is active are partial snapshots. Download the JSON replay source to retain exact source actions and reproduce another format. Stop/discard/export never alters a live checkpoint. The HTTP interface is GET/POST `/api/individuals/:id/artifacts` and GET `/api/individuals/:id/artifacts/export/:format`; POST uses the standard command envelope plus `action: start|stop|discard`.

## Shared fixture capture

The shared garden has a separate explicit movement capture panel. Start requires an already running pair; it never starts or advances either fixture. Each committed two-participant frame contributes a complete action batch, with separate individual, session, dataset, model and checkpoint provenance. The authored shared flower arrangement is used by both the renderer and artifact mapping. Silence and rest remain valid; no notes or marks feed back into the neural workers.

Pause, separation, source changes or an invalid batch end capture with a disclosed partial prefix. Exports remain available after separation, until explicit discard or server shutdown. Capture actions use their own sequence, independent of shared controller commands. Requests recheck the current world after reading their bodies, and the UI preserves terminal states against delayed active replies. A new capture requires discarding the previous one. At most 64 source identities and 1,024 actions per capture are retained in memory.

GET `/api/shared/artifacts` lists retained captures. GET/POST `/api/shared/:id/artifacts` reads status or accepts `{protocolVersion:1, sharedId, worldEpoch, captureSequence, action}` with `start`, `stop` or `discard`. GET `/api/shared/:id/artifacts/export/:format` exports JSON, MIDI (`mid`), SVG or PNG. Download JSON to retain the complete replay source. This integration uses the synthetic fixture body controller; it does not establish full-connectome creativity or learned choices.
