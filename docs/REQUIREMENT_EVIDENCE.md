## Outcome taxonomy

Issue #16's first acceptance criterion asks for a **passed / failed / unavailable** result per requirement. The previous snapshot had no way to say *failed*, so an evaluated negative and an unbuilt capability both collapsed into "Partial". This matrix separates the two ideas into an **Outcome** and a **Scope**.

| Outcome | Meaning |
| --- | --- |
| **Pass** | Every acceptance clause the repository actually supports is substantiated by implementation plus a test or a recorded measurement at this revision, within the stated Scope. |
| **Unmet** | At least one material acceptance clause has no implementation and no test at this revision. Nothing was measured and failed; the work is simply not done. |
| **Negative** | The capability was built far enough to be evaluated, the evaluation ran to completion, and the recorded result is negative. A Negative row blocks the corresponding positive claim and may not be upgraded without new evidence. |
| **Unavailable** | The required capability does not exist in any form and no evaluation was possible. |

**Scope** is the evidence boundary, never an outcome. A Pass inside a narrow scope is a pass of a narrow contract and nothing more.

- **Fixture** — the synthetic 32-neuron runtime, its engineered home camera/contact, and optional language and creative output.
- **Full graph** — the separately identified MaleCNS v1.0 / BANC v888 sparse workers, with explicit paused loading, checkpoints and bounded instantaneous samples. Zero-drive stepping proves numerical execution only.
- **Dataset** — imported anatomical atlas and connectivity. Displaying anatomy does not prove neural execution.
- **Host factory** — in-process real service factories or fake-transport validation, plus the one isolated running-sequencer run in [live visitor fixture evidence](LIVE_VISITOR_FIXTURE_EVIDENCE.md). No live PortOS-managed deployment, no human observer, no full-graph travel follows from this.
- **Browser-measured** — a dated, recorded Chromium run, either the headless shell or real Chrome over CDP (`ANGLE (Apple, ANGLE Metal Renderer: Apple M5 Max …)`). `tests/browser/` is run by `npm run test:browser` only; it is deliberately not part of `npm test` and not in CI, so these figures are recorded measurements rather than guarded regressions.

**This is a taxonomy change, not a sudden capability jump.** Moving scope out of the outcome column moves many rows that previously read "Partial" to "Pass at Fixture scope" without any new capability existing. Read the Scope and Limit columns before quoting an outcome. The [PRD](../PRD.md) remains authoritative; the shortened row labels here do not replace its acceptance criteria.
