Issue links identify ownership; their open/closed state is deliberately not used as completion evidence.

**Pass** means the stated supported contract has direct implementation/test or recorded measurement evidence at this revision. **Partial** means material acceptance criteria remain unmet or evidence covers only a narrower fixture, numerical, browser or factory scope. **Unavailable** means the required capability/result does not exist. Tests linked below are specific reproducible evidence locations, not a claim that this documentation task reran them. Negative-requirement passes describe current supported schemas and disclosures, not an unrestricted guarantee.

Evidence boundaries:

- **Fixture:** synthetic 32-neuron runtime, engineered home camera/contact, optional language and creative output.
- **Full graph:** complete separately identified MaleCNS/BANC sparse workers, explicit paused loading, checkpoints and bounded instantaneous samples. Zero-drive stepping proves numerical execution only.
- **Dataset:** imported anatomical atlas/connectivity; displaying it does not prove neural execution.
- **Host factory:** in-process real service factories or fake-transport browser validation. No live-host visit, deployed observer or full-graph travel acceptance follows from this.
- **Recorded local browser:** [operational readiness](OPERATIONAL_READINESS.md) and [sample contract](CONNECTOME_SAMPLES.md) describe bounded checks. The root acceptance check read a Male sample at tick zero with unchanged command sequence; this is a read-only sample check, not neural/body-loop evidence.

## Opt-in acceptance runbook

Use an isolated checkout and fresh temporary data root. Record the exact commit, Node version, platform/architecture, graph/model hashes, configuration and commands with results. Never point recovery tests at the production data root. Follow [backup recovery](BACKUP_RECOVERY.md) for exclusive writers, fresh destinations and interrupted-restore handling.

1. Read [operational readiness](OPERATIONAL_READINESS.md), [research HTTP](CONNECTOME_HTTP.md) and the welfare charter. Inventory unavailable capabilities before selecting checks. A missing capability stays unavailable; never replace it with fixture results.
2. Run targeted small-fixture contract tests explicitly, for example `node --test server/connectome-registry.test.js server/connectome-store.test.js server/application-backup.test.js server/managed-visitor-bridge.test.js server/identity-shared.test.js`. These tests do not establish full-dataset behavior. Capture exit codes and failing cases; do not treat historical counts as a current result.
3. If datasets are needed, follow the explicit preparation workflow in [research HTTP](CONNECTOME_HTTP.md). Importing/verifying data does not authorize worker loading. Reuse only verified stages and keep graph bulk and memory evidence out of Git and backup archives.
4. Only after explicit operator authorization, use the commands and unchanged limits in [operating envelope](OPERATING_ENVELOPE.md). That tool requires `--measure`; its zero-drive single/pair measurements must remain labeled zero-drive. Stop on a failed bound; do not raise limits or switch to a probe to obtain a pass.
5. For an explicitly authorized isolated browser check, create an identity for the verified profile, load paused and confirm tick zero. Read one exact atlas neuron sample and compare individual, graph, epoch, tick and command sequence before/after. Start alone must not advance research time. An explicitly requested advance and a paused save/reload are separate checks; record their source epochs and exact clocks. Never present anatomical coloring as measured activity.
6. For fixture lifecycle/replay, use only a temporary store. Check selection changes, stale responses, pause/rest, checkpoint restore and read-only replay; verify replay cannot acquire control or invoke language. Back up only after writers stop, restore into a fresh root, compare selected heads/checkpoint hashes and confirm unloaded/paused startup.
7. Live visitor acceptance requires separately authorized broker/host configuration and an explicit grant. Follow [managed visitors](managed-visitors.md); do not discover, admit or deploy from this document automatically. Record actual service revisions, negotiated capabilities, observer visibility, expiry/revocation and confirmed return. Keep credentials, pixels and private histories out of published evidence. An in-process factory result must retain that label.
8. Retained learning, real visual embodiment, chemistry, full-graph recordings and multi-visitor journeys require their missing implementations and separate reviewed protocols. Follow the [benign learning preregistration](BENIGN_LEARNING_PROTOCOL.md) before any learning experiment. No learning run is authorized here, and a weight change or attractive trajectory cannot satisfy FR25.

Publish outcomes as pass/partial/unavailable with source scope, exact reproduction steps and negative results. Update this matrix only against verified merged revisions. Issue #16 remains open until its integrated acceptance criteria are independently demonstrated.
